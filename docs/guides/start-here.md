# Start with Paraxe

Paraxe has four layers: shared contracts/helpers in core, styling and recipes in design, Vue/React rendering components, and editable registry layouts. Your application owns routing, data, permissions, persistence, and external services.

Start with [installation and theming](install-and-theme.md), then [core composition](core-components.md) and [using blocks](using-blocks.md). AI tools should also read the [implementation guide](ai-implementation.md).

## Choose the available release

The [verified release status](../reference/release-status.md) tracks the coordinated rollout of registry 0.2.0, eighteen experimental blocks, and nine recipes. It records npm versions and deployment status. The previous registry 0.1.2 remains available.

For future development work, use the repository playgrounds and matching workspace packages until its coordinated release is published.

## Build around a job

1. Identify the audience, important decision, and useful next action.
2. Choose a block with the right layout or compose focused primitives.
3. Choose a recipe suited to the job. Suggested defaults are optional; preserve independent axes.
4. Replace sample data, branding, media, and destinations; connect actual integrations.
5. Improve reusable core gaps before adding local exceptions.
6. Check meaningful states, typecheck/build, then review desktop/mobile and keyboard use.

The [design formula](../block-and-recipe-formula.md) records the layout and typography/control balance behind recent blocks. [Recipe studio](../playground-navigation.md) helps compare them without discarding preset choices.

These guides are a growing foundation, developed alongside the blocks.
